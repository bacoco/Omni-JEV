# [P0] Implement a native-processing multimodal state adapter

**Planning ID:** `OJ-004`  
**Priority:** P0  
**Status:** Proposed; no experiment results yet.

## Goal

Expose the audited backbone through a small adapter instead of rebuilding its encoders. Preserve the native embedding baseline and make any intermediate-feature path explicit and testable.

## Dependencies

<!-- dependencies:start -->
- [OJ-001](OJ-001.md)
- [OJ-002](OJ-002.md)
<!-- dependencies:end -->

## Scope

- Use the pinned native processor and model input conventions; correctly forward audio from video, sampled frames, text, and their alignment metadata.
- Expose native global embeddings and optional segment/token memory with valid masks, modality identifiers, reliable positions, and complete provenance.
- Inspect contextualization, token ordering, causal/hybrid behavior, and extraction layers before claiming tokens contain joint audiovisual information.
- Add cache keys covering media hashes, model/adapter revision, preprocessing, sampling, layer, pooling, and dtype.
- Handle absent/corrupt inputs, truncation, multiple sources, and unsupported paths without silently changing semantics.

## Acceptance criteria

- [ ] Shape and modality-routing tests pass on small fixtures for every claimed path.
- [ ] Audio-on versus audio-off fixtures verify that the audio stream actually reaches the model.
- [ ] Native pooling parity is measured and token masks exclude padding or unwanted prompt positions.
- [ ] Cache invalidation tests cover producing-weight and preprocessing changes.
- [ ] No model-width constant or presumed subfolder is inherited from the conversation without configuration verification.

## Evidence to attach

A concise implementation/experiment report, pinned revisions, commands, results or failure reasons, and any changed assumptions. Do not present the plan itself as a successful run.
