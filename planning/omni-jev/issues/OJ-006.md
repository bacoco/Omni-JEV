# [P1] Add a BERT-like dynamic question and option encoder

**Planning ID:** `OJ-006`  
**Priority:** P1  
**Status:** Proposed; no experiment results yet.

## Goal

Test the explicit project hypothesis that a bidirectional condition encoder improves open-condition decisions. Reuse GLiClass/Laya-style patterns where suitable, but retain the native aligned text branch as the comparison.

## Scope

- Encode instructions and request-time candidate/rubric descriptions with a version-pinned BERT-like model chosen for the target languages.
- Implement learned alignment/projection and shared option scoring rather than a permanent task-label classifier.
- Reuse framework abstractions only after auditing their assumptions about feature pooling, batch dimensions, and labels.
- Apply per-question masks or independent batches so questions cannot contaminate each other.
- Compare the native text branch and BERT-like branch with the same state features, training labels, and compute accounting.

## Acceptance criteria

- [ ] New candidate sets can be supplied without changing the final layer vocabulary.
- [ ] Padding, option-order, unrelated-question, and variable-candidate-count tests pass.
- [ ] E05 reports accuracy, calibration behavior, training cost, and per-question inference cost.
- [ ] No automatic image-text alignment is assumed from equal vector dimensions.
