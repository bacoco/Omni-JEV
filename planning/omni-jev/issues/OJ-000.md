# Project synthesis and experiment roadmap

**Planning ID:** `OJ-000`  
**Status:** Research/development plan, not an implemented or evaluated model.  
**Planning date:** 2026-09-24.

## Product goal

Build an independent, non-generative decision model that evaluates text-defined questions against text, images, visual documents, video, audio, and their relationships. Return **Noul**, **Choice**, or **Score** values that application code can use in `if`, `else`, and `case` logic. Reuse pretrained weights and existing code as much as possible. Repository prose, code, and issues are English.

This is not simply ColPali with thresholded tags. Retrieval relevance is a useful baseline; the target is a correct distribution over the answers to a supplied condition. It is also not a proposal to build a new image/audio encoder from scratch.

## Three output types

Noul is the estimated probability of yes. Choice selects one item from supplied mutually exclusive options and retains their probabilities. Score evaluates concrete ordered rubric levels and returns the probability-weighted level index plus the distribution. Multiple compatible tags are multiple binary questions. A similarity, probability, rubric score, and confidence are not interchangeable.

Preserve missing-evidence and abstention status outside the three decision families. A video without a processed audio stream must not produce a fabricated negative answer to a speech question. Document exact interoperability rather than claim Jev wire compatibility in advance.

Primary contract references:
- https://docs.typesafe.ai/primitives/noul
- https://docs.typesafe.ai/primitives/choice
- https://docs.typesafe.ai/primitives/score

## Proposed architecture

    state media + context
             |
    native processor + pretrained multimodal backbone
             |
    global / segment / token memory, with masks and positions
             |
             +------ question and candidate/rubric descriptions
                                      |
                            native text OR BERT-like encoder
                                      |
                   global / MaxSim / cross-attention scorer
                                      |
                            question-local option logits
                                      |
                              Noul / Choice / Score

Use one principal backbone, not a serial Ovis -> ColBERT -> ColModernVBERT stack. Preserve a native global embedding reference before adapting intermediate states into a new multi-vector interface. A sequence of native segment embeddings is another useful middle ground. Hidden states are not automatically retrieval-aligned, and same-width BERT and image features are not automatically compatible.

A BERT-like condition encoder is an explicit hypothesis to test. Keep a native text-encoder control. Compare MaxSim trained on decisions with a small attention module under the same backbone/data setup. The attention variant may help relation binding but is not an assumed winner.

## Reuse strategy

Ovis-Omni-Embedding-3B is the principal *candidate to audit* for the full modality scope. Keep Ovis-VL-Embedding-2B as a visual-only comparison. Preserve native processing and the complete embedding path rather than immediately discarding its multimodal contextualizer.

Inspect GLiClass/GLiFormer for request-time labels and task/head abstractions, Laya for typed-option scoring, and ColBERT/colpali_engine for projections, masks, and late-interaction code. ColModernVBERT is a separate compact document model or later student, not another large stage after Ovis. Decider-Vision is a candidate existing decision baseline only after availability and interface verification.

## Experiments to run

1. Audit and pin artifacts; verify native paths, tensors, processor behavior, and real audio-from-video ingestion.
2. Define the contract and a source-grouped pilot benchmark before model-specific tuning.
3. Measure native global embeddings, a supervised global scorer, OCR/ASR-plus-text decision baselines where applicable, and an audited existing decision model.
4. Compare native text encoding with BERT-like condition encoding.
5. Compare whole-state, native-segment, and intermediate-token memory.
6. Compare discriminatively trained MaxSim with a small cross-attention head.
7. Compare frozen-backbone training against controlled adaptation.
8. Test audio-only/video-only/transcript-only/joint input, event order, and controlled audio offsets.
9. Calibrate outputs on a separate split and measure risk versus automated coverage.
10. Compress token count, feature width, and precision independently; consider a compact specialist only after a quality reference exists.

## What a useful benchmark must expose

Include global categories, small document details, wrong-label checkboxes, signatures in the wrong region, negation, spoken content, environmental sound, ordered actions, broad audiovisual coherence, precise temporal relationships, rubric levels, and absent/occluded evidence. Keep edits and alternate questions from the same source together in a split. Hold out whole condition families as well as new media.

A key audiovisual counterfactual is the same video and same soundtrack with a controlled offset. Topic matching can remain true while synchrony becomes false. Record sampling resolution and do not claim finer temporal accuracy than the observed input supports.

Measure actual decision errors, probability quality, accepted-error coverage, and full compute cost. Media decoding, first-state encoding, each additional question, cache validity, and memory storage all count. A batch of questions does not prove one shared state encoding.

## Initial boundaries

No benchmark or training run has been performed by this plan. No hardware budget, dataset size, production latency target, or tolerated error has been provided. These are to be recorded before final tests, not invented. Do not adopt author-reported retrieval leaderboards as decision results or normalized outputs as guaranteed calibrated probabilities.

Do not require a vector database for direct decisions. Do not make RL a prerequisite. Do not overwrite unrelated repository content or assign a software license without an explicit project decision and dependency audit.

## First milestone

A reproducible, audited baseline with a typed contract and a discriminating pilot dataset. The least complex model meeting the scoped goals wins; a result that global embeddings are sufficient is a successful research outcome, not a failure to build something elaborate.
