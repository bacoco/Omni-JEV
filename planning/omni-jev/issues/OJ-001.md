# [P0] Audit and pin candidate models, processors, licenses, and reusable code

**Planning ID:** `OJ-001`  
**Priority:** P0  
**Status:** Proposed; no experiment results yet.

## Goal

Establish an executable and reproducible dependency boundary before choosing a framework or copying a head. Ovis-Omni is the principal candidate for the complete modality scope, Ovis-VL is the visual-only reference, and neither has been executed in this planning package. A browser access failure must not be interpreted as evidence of non-release.

## Dependencies

<!-- dependencies:start -->
None.
<!-- dependencies:end -->

## Scope

- Inspect the official Ovis model repositories and select immutable revisions; record file layout, hashes, configs, tokenizer, processor, pooling, required libraries, and remote-code requirements.
- Audit native text, image, audio, video, and joint audio-video paths with tiny permitted fixtures. Record unsupported paths explicitly.
- Inspect GLiClass/GLiFormer current task/vision interfaces, Laya option scoring, colpali_engine masks and projections, and ColModernVBERT as a separate model. Verify Decider-Vision before admitting it as a baseline.
- Record upstream model/code licenses and redistribution constraints; do not automatically assign the whole project an upstream license.
- Create a capability/source manifest separating checked code, successful runtime tests, author claims, and unresolved items.

## Acceptance criteria

- [ ] A revision-pinned manifest and dependency/environment specification are committed.
- [ ] At least one usable baseline passes native smoke tests; unavailable alternatives have explicit exclusion reasons.
- [ ] Actual output shapes, pooling rules, processing limits, and tested device/precision are recorded.
- [ ] No mutable main branch, borrowed benchmark score, or generic AutoModel snippet is treated as proof of inference readiness.

## Evidence to attach

A concise implementation/experiment report, pinned revisions, commands, results or failure reasons, and any changed assumptions. Do not present the plan itself as a successful run.
